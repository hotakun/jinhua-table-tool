## 一、项目概述

金华聚火表格处理是一个 Windows 桌面应用，用于将"订小易"系统导出的销售订单和客户明细，批量转换为"优路达"导入模板格式。

v2.6 是在 v2.0（Python+Rust 融合架构）基础上，将 GUI 层从 tkinter/ttkbootstrap **整体重写为 PySide6（Qt for Python）**，Rust 引擎 DLL 保持不变。最初作为对比练习项目，现已转正为发布主线（v3.1.2 安装包已发布到 GitHub Releases）。

### 架构总览

```
PySide6 GUI (main.py, 单文件 1155 行)
│
│  QThread (EngineWorker) + ctypes FFI 直调（零子进程、无命令窗）
▼
Rust DLL (jinhua_engine.dll ← ..\D2Y\Rust\src\engine.rs)
│
├── calamine 0.26        读 .xls/.xlsx
├── rust_xlsxwriter 0.79 写 .xlsx
├── 全部业务逻辑（明细处理 / 订单8步流水线 / 商品统计）
└── extern "C" 导出 engine_process / engine_free
```

> **DLL 是共享的**：`D:\WFR\D2Y\`（tkinter 版）与 `D:\WFR\D2Y-pyqt\`（PySide6 版）用的是同一份
> `jinhua_engine.dll`，源码只有 `..\D2Y\Rust\src\engine.rs` 一处。引擎层的行为变更会同时影响两个 GUI。

## 二、v2.6 相对 v2.0 的改进点（历史）

### GUI 框架重写（tkinter → PySide6）

| 维度 | v2.0 (ttkbootstrap) | v2.6 (PySide6) |
|------|--------------------|----------------|
| 框架 | tkinter + cosmo 主题 | PySide6 + Fusion + 双套 QSS |
| 多线程 | threading.Thread + root.after | QThread + Signal/Slot（4 个信号） |
| 结果展示 | tk.Text 手拼字符串 + tag 上色 | QTextEdit HTML + QTableWidget 表格 |
| 商品明细 | 等宽文本 + 4 色 tag | QTableWidget（可排序 / 交替色 / 复制 / 拖列宽） |
| 布局 | pack() 固定 620×880 | QVBoxLayout/QHBoxLayout 弹性布局，可缩放（默认 660×820，最小 580×680） |
| 许可证 | MIT | LGPL（PySide6） |

### 新增功能

1. **启动 Splash 动画** — `MLSX.gif`（聚火品牌动图）+ 主窗口 400ms 淡入（QPropertyAnimation；检测到 WSLg 环境自动跳过淡入）
2. **暗色/亮色主题切换** — 右上角 ☽/☀ 按钮一键切换，QSS + QPalette 双重切换保证控件全覆盖；启动时强制亮色调色板，不受系统暗色主题影响
3. **SQLite 操作日志** — 每次执行（成功或失败）写入 `D:\订单表格\logs\operations.db`，字段含：时间、操作人（os.getlogin）、状态、订单数/客户数/商品数/匹配数、输出文件、两个复选框状态、错误信息、耗时 ms。写入失败静默，不影响主流程
4. **双 Tab 结果区** — 「处理结果」（HTML 富文本，未匹配项标红）+「商品明细」（4 列表格）
5. **? 帮助浮层** — 右上角 ? 按钮弹出所需文件路径说明（Qt.Popup，点击外部自动关闭），取代 v2.0 常驻的"使用说明" LabelFrame，节省版面
6. **快捷键** — Ctrl+Enter 执行、Esc / Ctrl+Q 关闭；状态栏常驻提示
7. **视觉细节** — GroupBox 卡片阴影（QGraphicsDropShadowEffect）、按钮 8px 圆角、绿色圆角进度条

> ⚠ **更新检测在本版已被移除**（v3.1.2 校正）：v2.6/v3.0 时期的文档曾记载"启动 2s 自动检查更新 +
> 双击标题手动检查"，但当前 `main.py` 内**已无任何更新检测代码**（无 `urllib`/`ssl`/`UPDATE_API`/
> `_ver_newer`，仅残留一个未被使用的 `QTimer` import）。因此 v3.1.x 客户端**不会提示升级**，升级需手动
> 下载安装包。仍带自动更新检测的是 tkinter 版 `..\D2Y\金华聚火表格处理_hybrid.py`（v2.0.1）：它读
> `releases/latest`，发现更高版本会弹窗并自动下载安装包 —— 也就是说 GitHub 上发布新 Release 后，
> **只有 tkinter 老版本会收到升级提示**。若要让 PySide6 版恢复该能力，参考 tkinter 版的实现补回即可。

### Rust 引擎要点（..\D2Y\Rust\src\engine.rs，659 行）

- **明细处理** `run_detail`：遍历 `D:\明细表格\*.xls[x]`（跳过 `~$`）→ 表头第 2 行按关键字定位列 → 逐行拼备注（`名称 规格 单位：单价*数量= 金额；`，含"赠品"则省略价格）→ 输出 `MXBG2\<文件名数字>.xlsx`，并在 T3（第 3 行第 20 列）写全部备注汇总
- **订单 8 步** `run_order`：读销售订单（客户单位取★后 3 字符起为地点名；联系信息按最后一个 `-` 拆出 11 位手机号/联系人）→ 经纬度匹配（**按客户单位代码匹配**，代码 = 第一个空格/★之前的字母数字转大写）→ 明细匹配（订单号与文件名数字互相包含）→ 按客户名合并（多单拼备注+"合并订单：N"）→ 备注重组（金额行求和"总金额：xx.xx元"+结算标记、多条备注编号）→ 追加客户信息行 + `聚火配送：日期`（**当天 12 点后算次日**）→ 读模板表头 → 输出 `优路达导入模板MMDD-<4位序号>.xlsx`（随机 1000-9999，与已有文件取 max+1 防重）
- **商品统计** `compute_stats`：按（名称,规格,单位）汇总订货数量 → 单位优先、名称次之排序，不同单位间插空行 → 等宽格式化（name=46 / spec=36 / unit=10 / qty 右对齐 6）→ 经进度回调以 `STATS:total|"行1","行2",...` 传给 GUI
- **结算状态四态**：`结算状态`/`结账状态` 列取值含"未结"→ 未结；合并后 未结+已结 混合 → 部分未结；含"已结"→ 已结；其余/空 → 无标记。备注金额行尾标 ` ♣♣`(未结) / ` ♣`(部分未结) / ` .`(已结) / ` ?`(空值或异常)，并写入模板「订单状态」列（`未结账-全部 ￥xx.xx` / `未结账-部分 ￥xx.xx` / `已结账` / `异常，请复核`）
- **FFI 协议**：
  ```
  engine_process(delete: u8, stats: u8, cb) -> *mut c_char   // 返回 JSON
  engine_free(ptr)                                            // 释放
  回调: cb(pct: u32, label: *const c_char)                    // label 带 STATS: 前缀时为统计数据
  返回 JSON: {"file","orders","customers","matched","products","no_coords":[],"path"}
  出错时: {"error":"..."}
  ```

### ⚠ 销售订单列识别（v3.1.2 踩坑记录）

`read_sales()` 按表头关键字认列，**大小写敏感地 `contains` 匹配**，历史实现是"单趟 if/else 赋值"，后面的列会覆盖前面的：

```
新版表头: c1=订单号 c2=外部订单号
  c1 '订单号'      -> map[on] = 1
  c2 '外部订单号'  -> map[on] = 2   <== 覆盖了 c1（"外部订单号" 也含 "订单号"）
→ 取到全空的外部订单号列 → 每行 order_no 为空 → match_details 全部 continue
→ 结果面板"匹配明细 0 单"、输出模板「订单号」列整列空白（v3.1.1 线上故障）
```

**v3.1.2 起改为两趟匹配**：第 1 趟只认精确列名（`is_exact_col()`：`客户单位`/`地址`/`联系信息`/`订单号`/`销售单号`/`备注`/`结算状态`/`结账状态`），第 2 趟才用 `contains` 兜底，且**已命中的字段不再被覆盖**，并显式排除含「外部」的干扰列。

**改表头/加列时的检查清单**：
1. 新列名是否包含既有字段的关键字（如"外部订单号""物流单号""地址备注"）？它会抢列。
2. 若抢列发生，表现为：该列数据全空/串列 → 输出模板对应列空白或错位。
3. 认列逻辑永远保持"精确名优先 + 不覆盖"；确需新增别名的，加到 `is_exact_col()` 里，不要放宽 `contains`。

### 联动点 / 修改注意事项

1. **改引擎输出格式必须三处同步**：engine.rs 的 `compute_stats` 等宽格式 ↔ main.py 的 `_parse_stats_line`（L1024）↔ TXT 导出对齐（`STATS_W`、`_pad`）
2. `_parse_stats_line` 用空格从右往左拆列 → **商品名或规格本身含空格时会拆错**（已知弱点，改表格列时注意）
3. **版本号三处同步**：`main.py` L35、`setup.iss` AppVersion/OutputBaseFilename、GitHub Release tag（v 前缀）
4. **下载源与旧版共用**：`hotakun/jinhua-table-tool`；安装包 `AppId=JinhuaJuhuo-Table-Tool` 与旧版一致，覆盖安装同一目录。注意 **v3.1.x 自身不会检查更新**，只有 tkinter 版 v2.0.1 会读 `releases/latest` 并提示升级到本版
5. 改 Rust 引擎后需重新编译并**复制 DLL 到两个目录**（见下文），dist/ 内打包的是构建时的副本
6. 暗色模式改样式时，`LIGHT_QSS`/`DARK_QSS` 与 `_toggle_theme` 里的 QPalette、`_show_path_popup` 的内联样式要一起改

## 五、构建与部署

### 开发环境
- Python 3.14 + PySide6（本机 `python3` = 3.14.3 装有 PySide6 6.11.1；`python` = 3.14.7 没有）
- PyInstaller 6.x
- Rust 1.85+（MSVC toolchain，仅改引擎时需要）
- Inno Setup 6（`C:\Program Files (x86)\Inno Setup 6\ISCC.exe`）

### 直接运行
```powershell
cd D:\WFR\D2Y-pyqt
pip install PySide6
python main.py
```

### Rust DLL 重新编译（如有引擎改动）
```powershell
cd D:\WFR\D2Y\Rust

copy target\release\jinhua_engine.dll ..\jinhua_engine.dll                  # tkinter 版
copy target\release\jinhua_engine.dll ..\D2Y-pyqt\jinhua_engine.dll         # PySide6 版
```

### 打包 EXE
```powershell
cd D:\WFR\D2Y-pyqt
python3 -m PyInstaller JinhuaH.spec --noconfirm    # 或 build_exe.bat（脚本里用 python，需先装 PySide6）
# 输出: dist\JinhuaH\JinhuaH.exe (--onedir, --noconsole)
# 校验: dist\JinhuaH\_internal\jinhua_engine.dll 应与根目录 DLL 哈希一致（md5sum 比对）
# 冒烟: start dist\JinhuaH\JinhuaH.exe 确认进程存在后 taskkill 关闭
```

### 制作安装包
1. Inno Setup 编译 `setup.iss`：
   ```
   "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" setup.iss
   ```
2. 输出 `installer\金华聚火表格处理_v3.1.2_Setup.exe`（约 37 MB，lzma2/ultra64，耗时 ~50s）
3. 安装包会清理旧版残留（jinhua_engine.exe、JinhuaJuhuo.exe、*.pyc、*.spec）

### 发布（gh CLI）
```
gh release create v3.1.2 "installer\金华聚火表格处理_v3.1.2_Setup.exe" ^
  -R hotakun/jinhua-table-tool ^
  --title "v3.1.2 修复：匹配明细 0 单 / 输出模板订单号列空白" ^
  --notes-file release_notes.md
```
- tag 用**小写 `v`**（tkinter 老版的 `_ver_newer` 里是 `lstrip("v")`，大写 V 会导致版本号解析异常）
- 资产名需以 `.exe` 结尾且含 `Setup`（老版客户端的下载筛选条件）；GitHub 会剥掉文件名里的中文，实际显示为 `_v3.1.2_Setup.exe`，不影响筛选与下载（老版走 API 返回的 `browser_download_url`）
- 上传后确认它成为 `releases/latest`：`gh release view -R hotakun/jinhua-table-tool --json tagName` —— 这一步决定 tkinter 老版客户端能否收到升级提示
- 注意 only tkinter 版 v2.0.1 会读取并提示升级，v3.1.x 自身不会

## 七、版本历史

- **修复严重故障：匹配明细 0 单 / 输出模板「订单号」列整列空白**

- 文档补齐：订单号/结账状态识别规则、结算状态四态标记、经纬度按代码匹配、构建与发布命令实环境校验

## 八、已知限制

1. D 盘硬编码路径，不支持自定义
2. 仅支持 .xls/.xlsx
3. Windows 专用（os.startfile、os.getlogin）
4. 依赖联系信息列格式 `名称-手机号`（11 位、1 开头）；不符合时手机号留空、整串落到"客户经理"列
5. `_parse_stats_line` 对含空格的商品名/规格解析不准
6. Rust 引擎单线程
7. 经纬度匹配按客户单位代码（第一个空格/★之前的字母数字）匹配，同一代码取第一条，无模糊匹配
8. 操作日志无查看界面（需外部工具打开 operations.db）
9. 结算状态依赖列值含「未结」/「已结」（新版「结账状态」= 未结算/已结算，旧版「结算状态」）；列为空或措辞不符 → 输出「异常，请复核」（实测 386 单中 9 行结账状态为空）
10. 明细处理的列定位按第 2 行关键字（商品名称/规格/单位/实际价格/订货数量/金额/备注），缺列时取 0 号列兜底，不报错
11. **PySide6 版无自动更新检测**，新版本需手动下载安装包；只有 tkinter 版 v2.0.1 会自动提示
